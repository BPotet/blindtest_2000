<objective>
Deliver the first authoring capability on top of the walking skeleton: a logged-in host creates a quiz by title, sees it appear in a real list backed by Postgres, and can delete it. The list carries every state the UI-SPEC pins — empty, loading, error with retry, populated, French pluralization, and long-title truncation.

Purpose: the quiz is the container every question in plans `01-03` through `01-05` hangs off. It also establishes the host-ownership scoping pattern (`requireHost` + `hostId` filter) that every later route reuses.
Output: the `quizzes` table, four host-scoped REST routes, the quiz list page, and the shared `Quiz` contract types.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `/api/quizzes*` | Untrusted: quiz title body, `:id` path param, cookie. |
| One host's session → another host's data | The multi-tenant boundary. Every quiz row belongs to exactly one host and must be unreachable from any other session. |
| API → PostgreSQL | Parameterized Drizzle queries only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-08 | Elevation of Privilege | `repositories/quizzes.ts`, `routes/quizzes.ts` | high | mitigate | Ownership is enforced in the data layer: every repository function takes `hostId` first and every query filters `eq(quizzes.hostId, hostId)`, so a route that forgets the check still cannot read foreign rows. Gated by a criterion counting `hostId: string` parameters and by a two-host isolation test. |
| T-01-09 | Information Disclosure | `GET`/`DELETE /api/quizzes/:id` | medium | mitigate | A quiz belonging to another host returns 404, not 403 — the API never confirms that an id exists outside the caller's scope, so quiz uuids are not enumerable. Asserted directly in `quizzes.test.ts`. |
| T-01-10 | Tampering | Quiz title input | medium | mitigate | zod validates the title as a trimmed string of length 1–120 before it reaches the database, capping storage abuse and rejecting empty titles. React escapes the title on render, so a title containing markup is displayed as text rather than parsed — no `dangerouslySetInnerHTML` is introduced anywhere in this plan. |
| T-01-11 | Denial of Service | Unbounded quiz creation per host | low | accept | Local-only phase, single developer, server bound to `127.0.0.1`. Per-host quotas belong with the hosting milestone alongside the clip-retention policy flagged in PITFALLS.md Pitfall 7. |
| T-01-12 | Tampering | Cascading delete of a quiz | medium | mitigate | Deletion is gated behind an explicit `ConfirmDialog` in the UI and behind `deleteQuizForHost` (host-filtered) on the server; the `questions.quiz_id` foreign key added in plan `01-03` uses `onDelete: 'cascade'` so no orphan question rows or orphan clip records survive a quiz deletion. |
| T-01-SC | Tampering | npm/pnpm package installs | high | mitigate | This plan installs no new package — it consumes only dependencies already resolved, verified, and lock-pinned by plan `01-01`. If any install becomes necessary, apply plan `01-01`'s automated `npm view` verification before adding it. |
</threat_model>
