# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** Host-facing views only — signup/login, quiz list, question editor (YouTube URL + timestamp form, extraction status, clip preview/playback, re-cut control, upload-fallback form, answer + decoys form). No player-facing UI exists yet (Phase 2/3). Local-only, desktop-first (host is a creator at a keyboard, not a phone-in-hand player). Language: French (matches PROJECT.md/ROADMAP.md/REQUIREMENTS.md/openspec — all copy below is French).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — greenfield repo (confirmed: no `components.json`, `tailwind.config.*`, or `package.json` yet exist anywhere in the repo). No interactive prompt channel was available in this research session to run the shadcn Y/n gate, so per the orchestrator's explicit scope note ("pragmatic for a solo/small-project build — no need for a heavyweight component library") the default call is **manual CSS, no shadcn**. This is a reversible default, not a locked-in constraint — flagged for confirmation in the return summary. |
| Preset | not applicable |
| Component library | none — plain React 19 function components + CSS Modules (co-located `*.module.css` per component; zero extra runtime dependency, standard Vite support, keeps styling scoped without a build-time CSS framework commitment this phase doesn't need). |
| Icon library | `lucide-react` — tree-shakeable, no CSS framework dependency, covers every icon this phase needs (play, pause, upload, check-circle, alert-circle, loader, scissors/re-cut, trash, plus, log-out). |
| Font | System UI stack: `-apple-system, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` — no web-font loading dependency for a local-only phase; revisit only if a v2 visual identity pass is scoped. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inline padding |
| sm | 8px | Compact element spacing (form field internal padding, chip/badge padding) |
| md | 16px | Default element spacing (gap between form fields, list row padding) |
| lg | 24px | Section padding (card padding, form section padding) |
| xl | 32px | Layout gaps (gap between page header and content, between quiz-list cards) |
| 2xl | 48px | Major section breaks (top-of-page margin below nav) |
| 3xl | 64px | Page-level spacing (auth page vertical centering offset) |

Exceptions: Icon-only buttons (delete question, re-cut trigger, play/pause) use a 44×44px minimum touch/click target regardless of the icon's own visual size (accessibility floor — host may use this on a laptop trackpad or tablet).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label/meta | 14px | 400 (regular) | 1.5 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading (section/card title) | 20px | 600 (semibold) | 1.2 |
| Display (page title) | 28px | 600 (semibold) | 1.2 |

Exactly 2 weights used across the phase: 400 (regular, all body/label/input text) and 600 (semibold, all headings + primary button labels + status badges). No other weights.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, main content canvas |
| Secondary (30%) | `#F1F5F9` (slate-100) | Cards, question-list rows, quiz-list rows, top nav bar surface, form panel backgrounds |
| Accent (10%) | `#7C3AED` (violet-600) | Reserved for: primary CTA buttons (`Créer mon compte`, `Se connecter`, `Créer un quiz`, `Ajouter une question`, `Extraire le clip`, `Enregistrer la question`), active nav/tab underline, text-input focus outline/ring, links |
| Destructive | `#DC2626` (red-600) | Reserved for: delete quiz, delete question, remove decoy (when more than one exists), discard-unsaved-recut confirmation button |

Additional semantic tokens (needed beyond the 60/30/10 base because clip-extraction status is a hard requirement of QUIZ-01/02/03 and must be visually distinct from the accent/destructive roles above):

| Role | Value | Usage |
|------|-------|-------|
| Success | `#16A34A` (green-600) | Clip status badge "Prêt", success toast after extraction/upload/save |
| Warning/Pending | `#D97706` (amber-600) | Clip status badge "Extraction en cours…" |
| Text primary | `#0F172A` (slate-900) | Body text on white/slate-100 surfaces |
| Text muted | `#64748B` (slate-500) | Secondary/meta text (timestamps, question counts, helper text) |

Accent reserved for: the 6 primary CTAs listed above, focus rings, and links — never used for status badges (success/warning/destructive own their own colors) and never used as a decorative fill.

## Visual Hierarchy (focal points)

| Screen | Primary focal point |
|--------|----------------------|
| Login/signup | The form itself, vertically centered — the primary CTA button is the single accent-colored element on the page |
| Quiz list (empty) | The "Créer un quiz" CTA — only accent element visible |
| Quiz list (populated) | The list of quiz cards; CTA moves to a persistent top-right position, no longer the sole visual anchor |
| Question list | The "Ajouter une question" CTA when empty; once populated, the clip status badges (Success/Warning/Destructive colors) are the primary scan target — hosts need to spot failed extractions at a glance |
| Question editor | The clip status badge + preview player — the YouTube URL/timestamp form is secondary once a clip exists |

## Accessibility — icon-only buttons

All icon-only buttons (no visible text label) MUST carry an `aria-label` in French naming the action, matching the icon's intent:

| Icon-only button | `aria-label` |
|---|---|
| Delete quiz | `Supprimer ce quiz` |
| Delete question | `Supprimer cette question` |
| Remove decoy | `Supprimer ce leurre` |
| Re-cut clip | `Re-couper le clip` |
| Play/pause clip preview | `Lire le clip` / `Mettre en pause` (toggles with state) |
| Remove/change uploaded file | `Changer le fichier` |
| Logout (if icon-only in nav) | `Se déconnecter` |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 22 covered, 3 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Login/signup form | ✅ covered | Both forms render unfilled with placeholder text (`vous@exemple.com`, `••••••••`); no dedicated empty-state graphic needed — a bare form is its own empty state. |
| loading | Login/signup form | ✅ covered | Submit button shows a spinner icon, replaces its label with nothing (icon-only during load), and disables both inputs + button until the request resolves. |
| error | Login form | ✅ covered | See Copywriting Contract row "Error state — login wrong credentials"; rendered as inline text below the password field, not a toast. |
| error | Signup form | ✅ covered | See Copywriting Contract row "Error state — signup duplicate email"; includes a link to the login page. |
| partial | Login/signup form | ✅ covered | Client-side validation blocks submit while any required field is empty; the first invalid field gets focus + a red inline message on submit attempt. |
| empty | Quiz list | ✅ covered | See Copywriting Contract rows "Empty state heading/body — quiz list". |
| loading | Quiz list | 🧪 backstop | Skeleton rows (3 placeholder cards, secondary-color background, no text) render while the list fetches — visual-only state, no explicit assertion beyond "a loading state exists and is not a blank white screen". |
| error | Quiz list | ✅ covered | See Copywriting Contract row "Error state — generic network/server failure", with a `Réessayer` retry button in place of the list. |
| populated | Quiz list | ✅ covered | Each row shows: quiz title (heading style), question count, created date (muted text), and a delete icon-button; sorted newest-created-first. |
| zero-one-many | Quiz list | ✅ covered | Question count uses French pluralization: `1 question` vs `3 questions` (no plural "s" at exactly 1). |
| overflow | Quiz list | 🧪 backstop | Long quiz titles truncate with CSS `text-overflow: ellipsis` at one line; the full title is available via the native `title` HTML attribute on hover. Visual truncation behavior, not independently testable beyond a snapshot. |
| empty | Question list (within a quiz) | ✅ covered | See Copywriting Contract rows "Empty state heading/body — question list". |
| populated | Question list | ✅ covered | Each row shows: order number, clip status badge (Prêt/En cours/Échec — Success/Warning/Destructive colors respectively), a truncated preview of the correct answer, and edit/delete icon-buttons. |
| zero-one-many | Question list | ✅ covered | Same French pluralization rule as quiz list question counts. |
| empty | Clip preview / media player | ✅ covered | See Copywriting Contract row "Empty state — clip preview (no clip attempted yet)". |
| loading | Extraction status (YouTube URL + timestamp form) | ✅ covered | While extraction runs: form disables, status badge shows "Extraction en cours…" (Warning color) with a spinner; after 15s elapsed the badge text updates to "Cela prend un peu plus de temps que prévu…" without changing color, to reassure the host the request is still alive (default set here — no upstream spec pinned an exact threshold). |
| error | Extraction status | ✅ covered | On failure: badge flips to "Échec de l'extraction" (Destructive color) and the upload-fallback form appears immediately below, per QUIZ-03 / spec scenario "Extraction failure is detected and surfaced". See Copywriting Contract row "Error state — extraction failed". |
| populated | Clip preview / media player | ✅ covered | Ready clip renders a standard HTML5 `<audio controls>` element (play/pause/scrubber/volume — native, no custom waveform build this phase) plus the "Prêt" success badge and the "Re-couper le clip" secondary action. |
| partial | YouTube URL + timestamp form | ✅ covered | Inline validation: malformed URL or non-numeric/negative timestamp blocks the "Extraire le clip" button (disabled state) with an inline message identifying which field is invalid. |
| empty | Upload fallback form | ✅ covered | Renders a dashed-border drop zone with copy `Glissez un fichier audio ici, ou cliquez pour parcourir` — only visible once extraction has failed for that question (never shown pre-emptively, per spec scenario "Upload fallback is not offered when extraction already succeeded"). |
| loading | Upload fallback form | ✅ covered | Shows a determinate progress bar (percent-based, using the upload's native `progress` event) while the file transfers. |
| error | Upload fallback form | ✅ covered | See Copywriting Contract row "Error state — invalid upload file"; validated client-side (extension + size) before the request is sent, and re-validated server-side. |
| populated | Upload fallback form | ✅ covered | Once a file is selected/uploaded, the drop zone is replaced by a compact file chip (filename + size + a small remove/change icon-button). |
| empty | Answer + decoys form | ✅ covered | Renders with the correct-answer field and exactly one decoy field pre-shown (minimum viable QCM), plus the "Ajouter un leurre" secondary action to add more. |
| zero-one-many | Answer + decoys form | ✅ covered | A per-decoy remove icon-button appears only when more than one decoy row exists — the form never allows removing the last remaining decoy, keeping "one or more decoys" always satisfied without a dead-end empty state. |
| partial | Answer + decoys form | ✅ covered | See Copywriting Contract row "Error state — incomplete question on save"; the "Enregistrer la question" button stays enabled (host can attempt save) but the server/client validation message names exactly what's missing, per spec scenario "Incomplete question cannot be saved". |
| long-text | Answer + decoys form | 🧪 backstop | Answer/decoy text inputs are full-width and allow wrapping in their own row on save/preview (not truncated) since these values matter for correctness, not just display — visual wrap behavior, not independently unit-testable. |
| overflow | Nav (top bar) | ✅ covered | Host email/name in the account menu truncates with ellipsis at a fixed max-width if unusually long; full value available in the menu's expanded dropdown. |
| loading | Nav / app shell | ⚠ unresolved | Exact behavior of the app shell during the initial session-check (better-auth cookie validation) before redirecting to login or showing the quiz list — e.g. blank screen vs. spinner vs. skeleton — was not specified upstream and is left as a planner assumption (recommend: full-page centered spinner, no flash of unauthenticated content). |
